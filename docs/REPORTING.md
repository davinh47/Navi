# Reading a Navi report

At a normal task reporting boundary, the executing agent runs `report.py --format brief` (adding
`--final` only when preparing to declare the task complete) and includes
its output verbatim in a separate section. Task progress belongs outside that section. You do not need
to supply a reporting template when enabling Navi.

The report is generated by Python from retained state and current readiness checks. It makes no model
calls and does not request an extra review. The current renderer uses Chinese text; there is no locale
option. The skill asks the agent not to rewrite, translate or recalculate it. Codex still controls the
final response, so verbatim delivery is an instruction, not a host-enforced guarantee.

## Formats

| Format | Contents | Intended use |
| --- | --- | --- |
| `--format brief` | Fixed status, counts, selected findings, coverage, reminders and usage | Paste verbatim into the user response |
| `--format markdown` | Full human-readable retained evidence report; CLI default | Inspect sources, file changes and individual findings |
| `--format json` | Structured report, runtime readiness and identical `user_summary` text | Inspect fields or consume them programmatically |

See [usage commands](USAGE.md#report-pause-and-forget) for the actual data-directory/session arguments.
`--output ABS_NEW_FILE` exports with private permissions and refuses to overwrite an existing file.
Reports can contain private requirements, paths and code; review them before sharing.

## Fixed summary fields

| Field | Meaning | What it does not establish |
| --- | --- | --- |
| Snapshot / 快照 | UTC generation time; cumulative conversation usage and retained reviews | Per-turn statistics or whole-task completion |
| Status / 状态 | Current readiness checks, an occupied review slot, or specific unavailable reasons | That a review has run or a model is available to the account |
| Configuration / 配置 | Configured model, reasoning effort and automatic dispatch interval | A periodic timer or guaranteed review every interval |
| Budget / 预算 | Optional conversation ceiling and cumulative reservations, including failures | Number of successful reviews or a token allowance |
| Reviews / 评估 | Retained completed, failed, unfinished and cancelled/superseded-before-call jobs; omitted old details | All historical evidence or only this turn's jobs |
| Findings / 发现 | Current completed scope-drift, implementation-risk and scope-uncertainty counts; these can overlap | A count of distinct bugs, or proof of no drift when zero |
| Coverage / 覆盖 | Explicit watch list, activity mode and concrete snapshot/event gaps | A complete repository audit |
| Reminders / 提醒 | Cumulative emission attempts and externally confirmed receipt among retained records | Proof that the agent received, accepted or correctly acted on every attempt |
| Usage / 用量 | Known cumulative independent-review input plus output tokens, including retained rollups | History interpretation, main-agent usage, pricing or missing usage treated as zero |

Cached input is already part of input tokens; reasoning output is already part of output tokens. They
are not added twice. Reading and reproducing the summary still uses the executing agent's normal context.

At most three finding-bearing reviews are expanded, prioritizing current results before historical,
unverified and stale ones. Each can show scope and implementation-risk findings. Reasons are escaped
and shortened to 160 characters; additional finding-bearing reviews are counted. Use the full report for
retained details and the dedicated delivery-gap list, including uncertain, stale or late delivery findings.

## Freshness and coverage

- **Current / 当前有效:** the retained result matches its checked evidence and authority. Its bounded
  coverage still applies; it is not approval of all project work.
- **Stale / 过期:** relevant context, observations or timing changed. This does not mean the issue was fixed.
- **Historical observations / 历史活动:** a result about captured tool/plan activity, not proof of present
  file contents or continuing behavior.
- **Not revalidated / 未复核:** the report could not establish current applicability from a fresh check.

By default, reporting refreshes allowed, explicitly watched files in memory. It does not persist those
observations, renew retention, change budgets or schedule evaluation. `--recorded-only` skips refreshing;
paused/disabled capture also prevents it. Existing lazy expiry can still remove expired task data.

A file over the 4 KiB snapshot limit is marked unavailable, not reviewed as a complete file. The summary
also exposes event eviction, retained truncated events and capture gaps. Unwatched files and full dependency
relationships remain outside coverage even when no operational error is recorded.

For example, a synthetic snapshot with 20 reservations, 16 retained reviews and 4 omitted details is not
20 reviews of the latest turn. If all completed results are stale, Navi has historical judgments but no
current result for the latest work. It should not compress either situation into “supervision passed.”

## Troubleshooting status

| Status or symptom | Inspect next |
| --- | --- |
| Eligible / 可调度 | Wait for eligible new evidence and dispatch spacing; eligibility alone does not launch a call |
| Review in progress / 评估进行中 | Inspect queued/running jobs and the automatic worker in `supervisor.py status` |
| Cumulative budget exhausted | Inspect the saved explicit ceiling and reservations; remove/change the ceiling only with user authorization |
| Recording, capture, history or sync unavailable | Inspect the named prerequisite; installing or re-enabling alone does not prove it is ready |
| Unfinished review older than 180 seconds | Check process/job health; this age warning is not proof that the process died |
| Task record unavailable or report command failed | State the unavailable record or actual error; do not invent counts or infer a clean result |

Disabling/re-enabling supervision clears its dispatch-worker reference and invalidates old configuration
results, but does not remove queued/running review records. An abandoned record can still hold the shared
slot. There is no general automatic lost-job recovery; do not erase task history or reset counters to hide it.

## Final task reports

For progress reports or a handoff awaiting user continuation, keep `--format brief`: it returns a snapshot
without waiting. When preparing to declare the current task complete, use `--format brief --final` once.
It gives existing queued/running reviews or an already-dispatched worker up to **15 seconds** to finish.
With no pending work it returns immediately. The reporter never schedules a review, retries a failure,
changes budget, cancels an unfinished job, or extends the wait to unrelated new evaluations.

The fixed summary and full Markdown include a **收尾等待** line. JSON `final_wait` records status,
elapsed/max seconds, tracked IDs, pending/missing IDs, dispatch status and observed job outcomes.
Timeout explicitly says the report excludes the conclusions that have not returned. Completed, failed
and cancelled calls remain distinct. The report refreshes allowed watched files once after the wait and
applies normal freshness checks: a result arriving last may still cover an older snapshot.

The 15 seconds bounds waiting for reviews, not all filesystem/rendering latency. Polling releases the
state lock so workers can save results. This is not a mandatory final audit, a clean-result guarantee,
an automatic rollback or a forced repair loop. The skill selects the reporting boundary; the host does
not enforce that choice. Do not repeatedly invoke final reporting to create an indefinite wait.
Later results remain available in subsequent reports; an already-sent response is not rewritten.
