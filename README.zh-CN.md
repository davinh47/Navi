# Navi

**为长任务 Coding Agent 增加独立的范围监督。**

[English](README.md) · [安装](docs/INSTALL.md) · [架构](docs/ARCHITECTURE.md) · [已知限制](docs/LIMITATIONS.md)

你要求修改 UI，Agent 却开始接入暂时不想连接的后端；一个小修复逐渐扩展成重构；
或者多轮“继续”后，执行偏离了原先计划。Navi 在选定检查点对照用户要求与实际观察到的动作，
向执行 Agent 提出范围提醒，并在正常汇报时向用户提供报告。

**提醒可接受、可质疑；不阻挡工具、不强制续轮、不自动回滚。**
Navi 以 Codex 插件的形式安装。

## 当前能力

- 保存有来源的用户要求、当前阶段、延后事项和范围变更。
- 观察显式指定文件及可选的有界工具活动。
- 通过独立、禁用工具的模型调用评估任务范围和实现风险。
- 检查未经授权的功能缩减、实现替代和与证据不符的完成声明；向 Agent 提醒，并在报告中单列交付缺口与待核验项。
- 将符合条件的范围提醒发送给执行 Agent；过度工程和狭窄特判目前仅记录。
- 在已有对话中导入历史，并在后续检查点增量补入新对话。
- 汇总证据、提醒、回应、用量与覆盖缺口；支持明确预览和用户确认后的选段文本回滚。

**实验性 alpha，目前实测目标为 macOS 上的 Codex。** 其他 Agent 适配尚未实现。
有误报、漏报及评估失败的可能，尚未证明总体检测准确率或能够节省净 token。

## 安装与开始使用

需要 Python 3.9+、Git、支持插件/Hook 的 Codex，以及你自己的 Codex 登录。
Navi 运行时仅使用 Python 标准库，无需安装 pip/npm 依赖。

```sh
codex plugin marketplace add https://github.com/davinh47/Navi.git
codex plugin add navi@navi
```

在插件/Hook 设置中审阅并启用 Navi，开启新会话加载插件。安装不等于自动采集所有项目。
不要同时启用来自两个 marketplace 的 Navi 副本。

在项目对话中，用一句话启用 Navi，后面接自己的任务内容：

> 用 Navi 监督这个任务。
>
> [你的任务内容]

长任务可以说“用 Navi 的长任务模式监督这个任务”。Navi 默认从当前对话读取该任务的原始要求和相关上下文，
无需另加历史读取指令，也无需重复任务内容；你明确限制历史读取时，会遵守该限制。
同一任务后续继续执行，无需重复启用。

Codex 会校验并导入真实对话记录、完成监督配置并确认状态。宿主记录不可用或格式不支持时，会说明具体缺口。
范围提醒发给 Codex，固定格式的程序生成摘要交给你，列出状态、评估、发现、覆盖缺口和用量。详见[使用与排障](docs/USAGE.md)和[报告字段说明](docs/REPORTING.md)。
报告区分同一对话的累计用量、保留的评估明细及当前有效结果，不把“可调度”或“零提醒”当作检查通过。
任务完成时，收尾报告最多等待已有评估 15 秒；中途汇报不等待。不会为此新增评估，超时或结果过期会明确说明。

## 用量与边界

| 档位 | 自动调度最小间隔 | 同一对话并发评估数 | 提醒冷却 |
| --- | ---: | ---: | ---: |
| standard | 30 秒 | 1 | 1 分钟 |
| long-task | 3 分钟 | 1 | 5 分钟 |

**不设每小时评估/调度上限，默认也不设累计次数上限。** 自动评估需要新的合适证据并满足最小间隔，
不代表定时检查或完整覆盖。手动、自动和复核共用同一对话的一个评估位置，不同对话互不占用。
评估期间执行 Agent 继续工作；间隔满足且位置空闲后，在下一次符合条件的原生事件重新检查。
持续有新证据时，长任务间隔允许每小时约 20 次自动评估；实际 token 消耗取决于证据和模型。
提醒仍单独去重和冷却。

用户可选设定同一对话的累计评估预算，已有消耗计入，继续、重启或换档不清零。达到预算后，
报告明确显示监督评估暂停；此前仍有效的提醒可以继续送达。不再为潜在复核预留最后一个名额。
具体命令见 [预算设置](docs/USAGE.md#review-budgets)。

提醒通过去重、冷却和过期检查控制频率。滚动保留最近 16 条评估和 48 条提醒明细；
报告会注明旧明细移出情况，保留累计次数和已取得的 token 总量，不承诺完整历史证据覆盖。

默认监督模型为 `gpt-5.6-luna` / high，可配置为账号可用模型。首次历史整理默认 Luna medium，
独立占用最多一次调用。

记录、增量读取、生成报告本身不调用模型；独立评估仍需发送有界上下文，可能产生可观消耗。
增量读取不等于只为新增文本付费。降低重复输入、改善长期预算和错误引用处理仍是后续工作。

仓库包含 338 项离线测试，覆盖状态、调度、证据、提醒、报告、回滚和包迁移。
可复现检查及其覆盖边界见 [验证说明](docs/VALIDATION.md)。
